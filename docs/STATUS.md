## 3. Блокеры запуска на Vercel (Production Blockers)

1. **Rate Limiter в памяти процесса (In-Memory Limiter):**
   - Текущий `rate-limiter.ts` хранит счетчики попыток и блокировок в памяти инстанса Node.js (`Map`). В serverless-среде Vercel каждый лямбда-инстанс изолирован, поэтому лимиты сбрасываются между вызовами. Требуется Upstash Redis / Vercel KV.
2. **Письма без провайдера (Development Email Driver):**
   - Сервис отправки почты (`email.ts`) по умолчанию эмулирует отправку в консоль. Для боевой среды на Vercel необходима интеграция с Resend (или SMTP/Postmark) и указание валидного `RESEND_API_KEY`.
3. **Отсутствие файлового хранилища (Object Storage):**
   - Vercel имеет read-only файловую систему в runtime. Файлы домашних заданий, аватары и материалы курсов не могут сохраняться на диск; требуется подключение S3 / Cloudflare R2 / Vercel Blob. Загрузки временно выключены или заменены на ссылки.
4. **Конфигурация `TRUSTED_PROXY_HOPS`:**
   - По умолчанию для локальной разработки и тестов прокси-проверка настроена на доверие к прямому соединению. На Vercel за Cloudflare/Vercel Edge Network необходимо строго выставить `TRUSTED_PROXY_HOPS=1` и настроить проверку заголовка `x-forwarded-for` для предотвращения подделки IP-адресов.
