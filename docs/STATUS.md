## 3. Что мешает Production-запуску (Production Blockers)

1. **База данных SQLite в однопоточном файловом режиме:**
   - Для продакшна необходим переход на PostgreSQL (или управляемый кластер), так как SQLite лочится на уровне файла при высокой конкурентной записи.
2. **Отсутствие реального хранилища файлов (Object Storage):**
   - Файлы домашних заданий и материалы курсов не загружаются в S3-совместимое хранилище (AWS S3, Cloudflare R2, MinIO); в API предусмотрены лишь URL-ссылки.
3. **Отсутствие интеграции с боевыми платежными провайдерами:**
   - Модуль платежей поддерживает только ручной учет, нет вебхуков для приема реальных онлайн-оплат (Payme / Click / Stripe).
4. **Dev-драйвер отправки почты:**
   - Подтверждение email и сброс паролей в текущей конфигурации выводятся в консоль/лог при отсутствии реального SMTP-транспорта (Resend, SendGrid, Postmark).
5. **Фоновые очереди задач (Background Jobs):**
   - Отправка email, пересчет задолженностей и деактивация просроченных подписок выполняются синхронно в HTTP-запросах; требуется Redis + BullMQ.
6. **WS/SSE транспорт уведомлений:**
   - Обновления статусов и уведомления работают только по polling запросам клиента.

## 4. Готово к демонстрации на Staging

1. **Полный цикл онбординга организации:**
   - Создание нового учебного центра через интерфейс платформы, назначение директора, генерация ссылок доступа.
2. **Многоуровневая система аутентификации и безопасности:**
   - Вход по паролю с защитой от перебора (блокировка по IP и глобальному счетчику).
   - Управление активными сессиями: просмотр списка устройств, завершение сессий на других устройствах.
   - Сброс пароля по одноразовому токену.
3. **Абсолютная изоляция тенантов и защита от IDOR:**
   - Директор Центра А ни при каких условиях не видит курсы, группы, расписание или персональные данные Центра Б.
   - Студент Центра А не может получить доступ к урокам или домашним заданиям другого центра даже при прямой подмене идентификаторов в запросах.
4. **Механизм мгновенной блокировки центра (Kill Switch):**
   - Администратор платформы может приостановить (`PAUSED`), заблокировать (`BLOCKED`) или аннулировать (`CANCELLED`) учебный центр.
   - Все пользователи заблокированного центра немедленно получают 403 `CENTER_SUSPENDED` на любых попытках чтения или записи, а разблокировка восстанавливает доступ без необходимости перелогина.
5. **Академический процесс обучения:**
   - Создание курса, наполнение модулями и уроками.
   - Генерация инвайт-кода для группы и регистрация ученика по инвайту.
   - Назначение домашнего задания преподавателем, сдача ответа учеником и выставление оценки.
6. **Журнал посещаемости:**
   - Отметка присутствия/отсутствия учеников с гарантированной защитой от гонок при параллельных запросах.
