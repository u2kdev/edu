## 4. Безопасность
- **Tenant Изоляция (centerId):** Строгая. Во всех бизнес-эндпоинтах используется `getTenantDb(tenantCtx.center.id)`.
- **Использование сырого `db`:** 
  - `src/lib/limits.ts`, `src/lib/notifications.ts`, `src/lib/tenant.ts`, `src/lib/auth.ts`, `src/app/api/tenant/staff/route.ts`, `onboarding/route.ts`. 
  - *Причина:* Глобальные платформенные сущности (пользователи, лимиты тарифов, логи аудита), не подлежащие строгой привязке к одному тенанту (или создающие его). Это безопасно.
- **Права:** Проверяются через `permissions.ts` матрицу ролей (`hasPermission`).
- **Блокировка центров:** При `PAUSED` и `BLOCKED` доступ через `requireTenantAccess` выбрасывает 403 `CENTER_SUSPENDED`.
- **Lockout / Rate Limit:** Хранится в оперативной памяти (в `Map`). *Слабое место:* Сбросится при рестарте сервера и не работает при кластеризации (нужен Redis).
- **dev-login:** Защищено. В `route.ts` строго проверяется `process.env["NODE_ENV"] === "production"` с отдачей 404.

## 5. Качество и Тесты
- **Всего тестов:** 149 (Сумма сходится с Vitest).
- **Покрытие БД:** Подавляющее большинство тестов (`e2e-journey`, `platform-organizations`, `tenant-isolation`, `register` и т.д.) работают на **реальной SQLite БД** (`test.db`). Моки БД удалены.
- **Падающие тесты:** При параллельном запуске падают 1-2 теста (напр., `register-limits.test.ts:35` и `password.test.ts:63`) из-за гонки времени и блокировок SQLite `Foreign key constraint violated`.
- **Костыли (try/catch):** В `tests/e2e-journey.test.ts` и `tests/register.test.ts` в блоках `afterAll` добавлены `try/catch` на удаление записей, чтобы при параллельном запуске один тест не ронял очистку другого.
