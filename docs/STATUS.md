# ОТЧЕТ О СОСТОЯНИИ ПРОЕКТА (LMS)
*Этап TRUST-3d + PostgreSQL: Полный аудит изоляции платформенных ролей, безопасная миграция данных, архивирование студентов и защита от каскадного удаления*

- **Каркас (Foundation): 100%** (Схема БД Prisma на PostgreSQL, строгая изоляция тенантов через инкапсулированный `tenantCtx.getTenantDb()`, глобальный запрет прямого импорта `@/lib/db-tenant` в `src/app/**` через ESLint, строгий read-only режим для PLATFORM_SUPPORT с возвратом 403 на всех пишущих роутах тенанта через AST-сканер и динамические `it.each` проверки, безопасный контекст платформенных ролей без записи в БД (`membership: undefined`), DMMF-валидация внешних ключей и `default-deny` на операции агрегации/группировки, криптостойкие инвайты, Docker Compose и GitHub Actions CI на PostgreSQL).
- **Минимально рабочий продукт (MVP): ~80%** (Ядро платформы, миграция на PostgreSQL c baseline-миграцией, транзакционная регистрация и принятие инвайтов, аутентификация и сессии с проверкой jti, архивирование студентов (`ARCHIVED`) с автоматическим исключением из расписания, посещаемости, списков групп и лимитов тарифа, защита удаления студентов с существующей историей через 409 с подсказкой «архивировать», строгая внутрицентровая изоляция ролей TEACHER/STUDENT/PARENT, журнал посещаемости с защитой от P2002, курсы, модули, уроки, оценки).
- **CI / Сборка / Стабильность:**
  - `tsc --noEmit`: 0 ошибок.
  - `vitest run`: все 60 тестовых файлов (319 тестов) стабильно зелёные на реальном PostgreSQL без флакающих тестов (0 failed).
  - Безопасная очистка членств платформенных пользователей в миграции `20261009192930_remove_platform_memberships`: удаляются только пустые DIRECTOR-членства имперсонации без ссылок, данные преподавателей/студентов с платформенной ролью полностью сохраняются.

## 3. Что мешает Production-запуску (Production Blockers)

1. **Отсутствие реального хранилища файлов (Object Storage):**
   - Файлы домашних заданий и материалы курсов не загружаются в S3-совместимое хранилище (AWS S3, Cloudflare R2, MinIO); в API предусмотрены лишь URL-ссылки.
2. **Отсутствие интеграции с боевыми платежными провайдерами:**
   - Модуль платежей поддерживает только ручной учет, нет вебхуков для приема реальных онлайн-оплат (Payme / Click / Stripe).
3. **Dev-драйвер отправки почты:**
   - Подтверждение email и сброс паролей в текущей конфигурации выводятся в консоль/лог при отсутствии реального SMTP-транспорта (Resend, SendGrid, Postmark).
4. **Фоновые очереди задач (Background Jobs):**
   - Отправка email, пересчет задолженностей и деактивация просроченных подписок выполняются синхронно в HTTP-запросах; требуется Redis + BullMQ.
5. **WS/SSE транспорт уведомлений:**
   - Обновления статусов и уведомления работают только по polling запросам клиента.

## 4. Готово к демонстрации на Staging

1. **Полный цикл онбординга организации:**
   - Создание нового учебного центра через интерфейс платформы, назначение директора, генерация ссылок доступа.
2. **Многоуровневая система безопасности и изоляции:**
   - Вход по паролю с защитой от перебора (блокировка по IP и глобальному счетчику).
   - Транзакционная защита от гонок при параллельной регистрации и принятии приглашений.
   - Запрет межцентрового доступа и перекрестных ссылок на чужие сущности.
3. **Механизм мгновенной блокировки центра (Kill Switch):**
   - Администратор платформы может приостановить (`PAUSED`), заблокировать (`BLOCKED`) или аннулировать (`CANCELLED`) учебный центр.
   - Все пользователи приостановленного центра получают отказ в доступе.
4. **Академический процесс обучения:**
   - Создание курса, наполнение модулями и уроками.
   - Генерация инвайт-кода для группы и регистрация ученика по инвайту.
   - Сдача ответа учеником и выставление оценки с разграничением прав.
5. **Журнал посещаемости и жизненный цикл студентов:**
   - Отметка присутствия/отсутствия учеников с гарантированной защитой от гонок при параллельных запросах.
   - Архивирование студентов (`ARCHIVED`) с высвобождением мест в лимитах тарифа и исключением из списков групп/расписания.
   - Защита от удаления студентов с бизнес-историей с дружелюбным 409 и рекомендацией архивации.
