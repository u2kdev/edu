# Чек-лист готовности к запуску в Production (Production Launch Checklist)

Данный документ представляет собой пошаговый контрольный список для проведения предстартовой проверки (Pre-Flight Checks) перед переводом платформы LMS в боевую эксплуатацию.

---

## 1. База данных (Database & Migrations)

- [ ] **1.1. Кластер Neon Postgres развернут**:
  - Создан проект в Neon в целевом регионе.
  - Включен транзакционный пулер PgBouncer (`DATABASE_URL`).
  - Проверено прямое подключение без пулера (`DIRECT_URL`).
- [ ] **1.2. Миграции применены на чистую БД**:
  - Выполнена команда `npx prisma migrate deploy` с использованием `DIRECT_URL`.
  - Все таблицы схемы Prisma созданы без ошибок.
- [ ] **1.3. Тарифные планы инициализированы**:
  - Тарифные планы созданы администратором или через seed-скрипт (`npm run prisma:seed`).
  - Убедиться, что в боевой среде автоматический fallback-план отключен (fallback создается только в тестах/dev).
- [ ] **1.4. Резервная копия базы данных перед запуском**:
  - Создан предварительный дамп: `pg_dump -d "$DIRECT_URL" -Fc -f initial_backup.dump`.

---

## 2. Переменные окружения (Environment Variables)

- [ ] **2.1. Конфигурация в Vercel Project Settings**:
  - [ ] `DATABASE_URL` — строка подключения через Neon Pooler с `sslmode=require&pgbouncer=true`.
  - [ ] `DIRECT_URL` — прямая строка подключения без пулера.
  - [ ] `JWT_SECRET` — сгенерирован криптографически стойкий секрет (не менее 32 символов).
  - [ ] `APP_URL` — канонический URL продакшен-домена (например: `https://lms.yourdomain.uz`).
  - [ ] `EMAIL_PROVIDER=resend` — установлен боевой драйвер отправки почты.
  - [ ] `RESEND_API_KEY` — указан валидный API-ключ от аккаунта Resend (`re_...`).
  - [ ] `EMAIL_FROM` — адрес отправителя совпадает с подтвержденным доменом в Resend.
  - [ ] `TRUSTED_PROXY_HOPS=1` — задано количество обратных прокси (для Vercel = 1).
  - [ ] `CRON_SECRET` — сгенерирован уникальный секрет для защиты Cron эндпоинтов.
  - [ ] `FEATURE_UPLOADS=false` — загрузки файлов отключены до настройки S3-бакета.
  - [ ] `DEV_LOGIN` отсутствует или установлен в `false`.
  - [ ] `DEV_EMAIL_LOG` отсутствует или установлен в `false`.

---

## 3. Безопасность и защита данных (Security)

- [ ] **3.1. Заголовки безопасности (Security Headers) активны**:
  - `Strict-Transport-Security` (HSTS): `max-age=63072000; includeSubDomains; preload`.
  - `X-Content-Type-Options`: `nosniff`.
  - `X-Frame-Options`: `DENY`.
  - `Referrer-Policy`: `strict-origin-when-cross-origin`.
  - `Content-Security-Policy` (CSP): строгие базовые директивы.
- [ ] **3.2. Безопасность сессионных Cookie**:
  - Атрибут `HttpOnly`: предотвращает чтение через JavaScript.
  - Атрибут `Secure`: передача только по HTTPS.
  - Атрибут `SameSite=Lax`: защита от межсайтовой подделки запросов (CSRF).
- [ ] **3.3. Блокировка Dev-поверхностей в Production**:
  - Запрос к `/dev/ui-kit` возвращает `404 Not Found`.
  - Запросы к тестовым эндпоинтам dev-login возвращают `404 Not Found` или `403 Forbidden`.
- [ ] **3.4. Отказоустойчивость лимитера (Fail-Closed Rate Limiting)**:
  - При сбое базы данных лимитер на критических маршрутах (`/api/auth/*`) возвращает `503 Service Unavailable`, не допуская деградации в неограниченный доступ в памяти.
  - Извлечение IP клиента защищено от спуфинга благодаря `TRUSTED_PROXY_HOPS=1`.

---

## 4. Почта и транзакционные уведомления (Email)

- [ ] **4.1. Подтверждение домена в Resend**:
  - В панели управления Resend добавлены и верифицированы DNS-записи: SPF, DKIM, DMARC.
  - Статус домена в Resend: `Verified`.
- [ ] **4.2. Тестовая доставка письма**:
  - Отправлено тестовое письмо для сброса пароля или регистрации.
  - Письмо доставлено во входящие без спам-пометок.
- [ ] **4.3. Очередь и повторная доставка (EmailOutbox)**:
  - В случае временной недоступности Resend API письмо сохраняется в таблице `EmailOutbox`.
  - Клиент получает успешный ответ, задача переходит на автоматический повтор фоновым процессом.

---

## 5. Фоновые задачи и расписание (Vercel Cron)

- [ ] **5.1. Конфигурация в `vercel.json`**:
  - Маршрут `/api/cron/cleanup` запланирован ежедневно в 03:00 UTC (`0 3 * * *`).
  - Маршрут `/api/cron/email-retry` запланирован каждые 10 минут (`*/10 * * * *`).
- [ ] **5.2. Проверка защиты `CRON_SECRET`**:
  - Прямой запрос без заголовка Authorization возвращает `401 Unauthorized`:
    ```bash
    curl -I https://lms.yourdomain.uz/api/cron/cleanup
    # Ожидается HTTP/2 401
    ```
  - Запрос с корректным Bearer токеном выполняется успешно:
    ```bash
    curl -I -H "Authorization: Bearer <CRON_SECRET>" https://lms.yourdomain.uz/api/cron/cleanup
    # Ожидается HTTP/2 200
    ```

## 6. Инициализация Первого Владельца Платформы (Superadmin Setup)

- [ ] **6.1. Создание первого суперпользователя**:
  - Либо через страницу `/setup` в браузере.
  - Либо через терминал командой `npm run setup:first-owner`.
- [ ] **6.2. Проверка постоянной блокировки мастера первичной настройки**:
  - Повторное обращение к `https://lms.yourdomain.uz/setup` возвращает ошибку `403 Forbidden` с сообщением о завершении настройки.
  - Повторный вызов `npm run setup:first-owner` завершается ошибкой и отказом.
- [ ] **6.3. Проверка входа в панель администратора**:
  - Вход под созданной учетной записью в `/login` выполнен успешно.
  - Доступ к `/admin` открыт.

## 7. Локализация и пользовательский интерфейс (I18N & UI)

- [ ] **7.1. Отсутствие хардкода**:

## 8. План отката и аварийное восстановление (Rollback & Backup)

- [ ] **8.1. Проверка процедуры отката на Vercel (Instant Rollback)**:
  - Команда ознакомлена с кнопкой «Instant Rollback» в панели Vercel Deployments.
- [ ] **8.2. Проверка процедуры восстановления БД**:
  - Проверена доступность функции Neon PITR в консоли управления БД.
  - Команда `pg_restore --clean --if-exists -d "$DIRECT_URL" backup_file.dump` протестирована в staging-окружении.
- [ ] **8.3. Контакты ответственных и каналы мониторинга**:
  - Назначены ответственные инженеры за инфраструктуру и безопасность.
  - Подключены алерты об ошибках (Sentry / Vercel Monitoring).
