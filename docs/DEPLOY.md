# Развертывание (Deployment Guide)

Данное руководство описывает развертывание платформы LMS в рабочей среде (Production / Staging).

---

## 1. Системные требования

- **Node.js**: v20.x или v22.x LTS (см. `.nvmrc`)
- **База данных**: PostgreSQL 15+ (рекомендуется PostgreSQL 16)
- **Менеджер пакетов**: `npm` v10+

---

## 2. Переменные окружения (Environment Variables)

Создайте файл `.env` на основе шаблона `.env.example`:

```bash
cp .env.example .env
```

### Основные переменные
- `DATABASE_URL`: Строка подключения к PostgreSQL (`postgresql://user:password@host:5432/dbname?schema=public`).
- `JWT_SECRET`: Секретный ключ для подписи JWT токенов (не менее 32 случайных символов).
- `DEV_LOGIN`: `false` для боевого окружения (запрещает dev-маршруты обхода входа).
- `DEV_EMAIL_LOG`: `false` для боевого окружения.

### Настройка доверенных прокси (`TRUSTED_PROXY_HOPS`)

> **ВАЖНО!** При развертывании приложения за любым reverse-proxy (Nginx, Traefik, Caddy, Cloudflare, AWS ALB, Vercel, Railway и т.д.) переменная `TRUSTED_PROXY_HOPS` является **СТРОГО ОБЯЗАТЕЛЬНОЙ**. Без неё реальный IP клиента не может быть безопасно определен, и все запросы будут классифицированы как IP `unknown`.

Переменная `TRUSTED_PROXY_HOPS` управляет тем, насколько приложение доверяет заголовку `x-forwarded-for` для определения реального IP-адреса клиента (`getClientIp`).

#### Архитектура блокировки и поведение при 0 hops (`TRUSTED_PROXY_HOPS=0`):

1. **Архитектурное решение Brute-Force Lockout (составной ключ `(email, IP)`):**
   - Блокировка перебора паролей (`LoginAttempt`) привязана к составному уникальному ключу `(email, ip)`.
   - Даже если приложение работает за прокси с `TRUSTED_PROXY_HOPS=0` (где все клиенты получают адрес `unknown`), блокировка одного аккаунта злоумышленником при переборе паролей (`victim@example.com`, `unknown`) **НЕ блокирует** остальных пользователей (`other@example.com`, `unknown`). Легитимные пользователи могут продолжать вход в систему.
   - Также действует лимит глобального перебора аккаунта (`email`, `GLOBAL`) при распределенной атаке с 20+ разных IP.

2. **Почему `TRUSTED_PROXY_HOPS` обязателен за прокси:**
   - Несмотря на изоляцию блокировки по `(email, IP)`, встроенный rate-limiter сетевого уровня (`checkRateLimit(ip)`) отслеживает частоту запросов по чистому IP. При значении hops=0 общий пул запросов для всех пользователей за прокси будет разделяться под ключом `unknown`, что может приводить к срабатыванию 429 Too Many Requests при интенсивном трафике.
   - Поэтому правильное указание числа доверенных прокси обязательно.

#### Как выбрать значение:

1. **`TRUSTED_PROXY_HOPS=0` (по умолчанию)**:
   - **Когда использовать**: Прямое подключение к приложению без обратного прокси или когда обратный прокси не заслуживает доверия.
   - **Поведение**: Все заголовки `x-forwarded-for` полностью игнорируются, возвращается `"unknown"`. Это гарантирует защиту от подделки IP злоумышленником.

2. **`TRUSTED_PROXY_HOPS=1`**:
   - **Когда использовать**: Приложение находится ровно за одним доверенным обратным прокси или балансировщиком нагрузки.
   - **Типичные конфигурации**:
     - Одиночный Nginx / Traefik / Caddy перед Node.js сервером.
     - Развертывание на Vercel, Railway, Render, Fly.io, Heroku.
     - AWS Application Load Balancer (ALB) напрямую перед ECS/EC2 контейнером.
   - **Поведение**: Берется 1-й IP-адрес справа в заголовке `x-forwarded-for` (добавленный вашим прокси).

3. **`TRUSTED_PROXY_HOPS=2`**:
   - **Когда использовать**: Приложение находится за двумя уровнями проксирования (например, Cloudflare CDN + Nginx ingress-контроллер).
   - **Поведение**: Берется 2-й IP-адрес справа в списке `x-forwarded-for`.

> **Внимание!** Установка `TRUSTED_PROXY_HOPS` больше фактического числа доверенных прокси позволяет злоумышленнику подделывать свой IP-адрес для обхода rate limiter и brute-force защиты.

Дополнительно:
- `TRUST_PROXY_HEADERS="true"`: Включает доверие заголовкам `cf-connecting-ip` (Cloudflare) или `x-real-ip`.

## 3. Сборка и запуск

1. **Установка зависимостей**:
   ```bash
   npm ci
   ```

2. **Генерация Prisma Client**:
   ```bash
   npx prisma generate
   ```

3. **Применение миграций БД**:
   ```bash
   npx prisma migrate deploy
   ```

4. **Сборка Next.js приложения**:
   ```bash
   npm run build
   ```

5. **Запуск сервера**:
   ```bash
   npm run start
   ```
